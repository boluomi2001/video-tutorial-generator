# 笔记结构与写作规范

> **本文件是「Agent 写笔记」模式的结构指南。**
> 核心原则：**一篇笔记只用一个结构，结构随这条视频的内容走 —— 不要套模板。**
> 下面的骨架是**参考**，不是必选清单。

---

## 一、通用外壳（所有笔记都必须有）

```
# <标题>
> 类型 ｜ 时长 ｜ 来源（+ 素材说明：转录 N 字 / 画面 OCR N 字）

## 速览                （一句话 + 3-6 条要点 + 适合谁）
<主体>                （自适应，见下）
## 音频文案            （取自 segments，带 mm:ss，原样保留）
```

- **标题** = 可读视频标题，格式 `{作者}：{描述首行}`
- **主体** 可以是一个或多个 `##` 小节，也可含表格
- **`## 音频文案` 必须保留**；无口播（转录为空）时写明"本条无口播"并附 BGM 署名

---

## 二、按内容选骨架（参考）

| 内容类型 | 骨架 | 判据 | 典型例子 |
|---|---|---|---|
| **观点说理** | 核心观点 → 论证 → 关键论据 → 适用边界 | 作者在讲一个判断/主张 | "买铲子=智商税"、"中层员工最易被替代" |
| **操作步骤** | 适用场景 → 前置条件 → 操作步骤 → 执行清单 → 避坑 | 有明确可执行动作 | 字幕 Skill、正话反说、人机双写 |
| **概念科普** | 是什么 → 怎么运作 → 例子 → 常见误解 → 延伸 | 解释一个概念 | Token 计费、提示词注入、AI 末世论 |
| **方法体系** | 方法论主张 → 框架/阶段 → 关键动作 → 易错点 | 讲一套方法 | 干中学、如何痛苦学 AI、蒸馏 |
| **工具项目** | 它是什么 → 上手复刻步骤 → 执行清单 → 限制 / 对比 | 介绍一个工具或项目 | 6 个 AI 项目架构、Vibe Coding、PDF 小工具 |
| **记录随笔** | 背景 → 内容脉络 → 观点与留白 → 金句 | 记录/分享/闲聊 | 等待 AI 工作时、90 天汇报、生日第 56 天 |
| **风格图鉴** | 清单表（名 / 英文名 / 一句话 / 画面特征）→ 家族归类 → 用法 | 列举型短片 | 30 种视觉美学风格 |

**混合内容**：以主体占比最大者为准，只选**一个**骨架，不要拼两个。

## 三、硬规则（都踩过坑）

1. **执行清单只在「操作步骤」「工具项目」里出现。**
   观点类、科普类、随笔类**不设**清单 —— 从根上杜绝"观点视频却列出 30 条步骤"的怪象。
2. **作者没讲的不许补。** 例：作者是在求助、没给答案，就如实写"视频没有给答案"。
   确需补充外部知识时，**必须标注来源**（如"〔官方资料〕browser4.io"）。
3. **参数 / 数值 / 工具名一律以转录 + OCR 为准。**
   不要再出现 `temperature=0.7`、`maxPages=100` 这类视频里根本没提的东西。
4. **同一观点全文只出现一次**（**语义**去重，不是删重复行）。
5. **同音误听必须校正**，并在「边界与注意」里列出。
   实测踩过的：`自适应组件 → 自摄用组件`、`Hyper3D Rodin → Hyper 3D Ready`、
   `Bang → Bomb`、`Blender → Bond`、`GPT → GBT/GP7`、`苍何 → 汤和`、
   `接进网页 → 接近网页`、`搭积木 → 搭机部`。
6. **长短随内容** —— 1 分钟视频不要写成 1 万字；也不要漏掉画面里才有的关键信息。
7. **表格优先于长段落**（用户偏好结构化、便于查阅）。
8. **命令 / 提示词 / 配置一律用代码块**，可直接复制。
9. **金额用 ¥**，遵循中文习惯。

## 四、反面教材（为什么不能套模板）

早期流水线用"**每章强套五要素**"的方式（步骤/注意/FAQ/参数/原理，一章一套）。
结果在一段 92 秒的纯口播视频上产出：

| 症状 | 实测数据 |
|---|---|
| 复读 | `npm install -g browser4-cli` 出现 **14 次**；`详细操作步骤`/`常见问题及解决方案`/`参数配置说明` **各 5 次**（一章一遍） |
| 编造 | 视频原话只有"两步"，笔记却编出完整 Puppeteer 脚本、JSON 配置、9 行参数表、FAQ 表 |
| 注水 | 861 字转录 → 17,692 字笔记（**20.5 倍**）；另一条 552 字 → 20,426 字（**37 倍**） |
| 脏数据 | 92 秒视频被切出"02:00-02:11"的章节（超出时长）；链接被截断成乱码 |

**结论：模板本身没错，错在把「时间片」当成了「知识点」。**
所以 Agent 写笔记时：**先读懂内容，再决定结构**；信息不足就少写，不要硬凑。

## 五、旧模板（仅传统 Qwen 模式使用，已不推荐）

以下两套模板是**传统模式**（不带 `--agent-write`）的输出格式，
保留仅作兼容/参考。Agent 写笔记模式**不要**用它们。

### 模板 A：项目复刻教程

```
---
title / author / date / category / tags / source
---
# <项目名>：从零到上线完整复刻教程
## 一、项目概述     ## 二、环境搭建      ## 三、逐模块实现（占比最大）
## 四、测试与调试   ## 五、部署上线      ## 六、个性化定制
## 七、完整工作流总结  ## 八、资源链接
```

### 模板 B：效率提升教学

```
---
title / author / date / category / tags / source
---
# <主题>：<核心能力>的效率提升教学
## 一、工具/方法概览  ## 二、安装与上手   ## 三、核心操作（占比最大）
## 四、进阶技巧       ## 五、竞品对比     ## 六、完整流程总结   ## 七、资源链接
```

两套模板的「知识点 5 要素」：详细操作步骤 / 关键注意事项 / 常见问题及解决方案 /
参数配置说明 / 原理简述 —— **每个知识点套一遍**（这正是上节"反面教材"的成因）。
